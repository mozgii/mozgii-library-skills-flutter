# Native Code With Dart Build Hooks

Build hooks let a Dart package compile or fetch its own native code, so a user runs `flutter run` and nothing else: no CMake edits per platform, no manual library copying. A hook is a Dart script that pub tooling runs automatically. Bindings then come from `ffigen`, so function signatures can't drift from the C header.

## Step 0: Check the Toolchain

```bash
dart --version
ls hook/ tool/ 2>/dev/null
clang --version || gcc --version
```

Build hooks need Dart 3.10. Link hooks and recorded-use tree-shaking need Dart 3.13. The host also needs a compiler: Xcode Command Line Tools on macOS (`xcode-select --install`), `build-essential` or Clang on Linux, and the Desktop development with C++ workload in Visual Studio on Windows. The examples were compiled, not run on a device, so load the library in a release build on each target you ship. The examples also import `ffi: ^2.2.0`, `test: ^1.33.0`.

## Choosing an Approach

| Situation | Choose | Why the others lose here |
|---|---|---|
| You have the C source, and users have compilers | Build hook with `CLibrary` | Prebuilt binaries add a release pipeline |
| Users shouldn't need a compiler | Build hook that downloads prebuilt files, verified by hash | Local compilation fails on bare machines |
| A library the OS already ships | `@Native` with a system asset, or `DynamicLibrary.process` | Bundling duplicates it |
| A large C API, and you use few functions | Add a link hook with `recordUse` | Unused native code stays in the app otherwise |
| Calling Java or Swift, not C | `jnigen` or `swiftgen` | C bindings don't apply |

## Worked Example: Wrapping a Small C Library

The package `fastsum` wraps one C function.

```text
fastsum/
├── hook/build.dart
├── lib/fastsum.dart
├── lib/src/c_library.dart
├── lib/src/third_party/fastsum.g.dart     # generated
├── third_party/fastsum/fastsum.c
├── third_party/fastsum/fastsum.h
└── tool/ffigen.dart
```

```bash
dart pub add code_assets hooks native_toolchain_c
dart pub add dev:ffigen
```

`hooks` and `code_assets` must be regular `dependencies`, because the hook runs in every consumer's build.

```c
// third_party/fastsum/fastsum.h
#ifndef FASTSUM_H_
#define FASTSUM_H_
#include <stdint.h>
int64_t fastsum(const int32_t *values, int64_t length);
#endif
```

One specification, shared by every hook, keeps the asset's identity in a single place. `assetName` must match the generated bindings' path under `lib/`, since that's the id `@Native` resolves.

```dart
// lib/src/c_library.dart
import 'package:native_toolchain_c/native_toolchain_c.dart';

final cLibrary = CLibrary(
  name: 'fastsum',
  assetName: 'src/third_party/fastsum.g.dart',
  sources: ['third_party/fastsum/fastsum.c'],
);
```

```dart
// hook/build.dart
import 'package:code_assets/code_assets.dart';
import 'package:fastsum/src/c_library.dart';
import 'package:hooks/hooks.dart';

void main(List<String> args) async {
  await build(args, (input, output) async {
    if (!input.config.buildCodeAssets) return;
    await cLibrary.build(input: input, output: output);
  });
}
```

Generate bindings with a script. Top-level declarations start excluded, so a visitor names the ones you want. The YAML config is deprecated as of `ffigen` 23.

```dart
// tool/ffigen.dart
import 'dart:io';

import 'package:ffigen/ffigen.dart';

Future<void> main() async {
  final root = Platform.script.resolve('../');
  await FfiGenerator(
    input: Input(entryPoints: [root.resolve('third_party/fastsum/fastsum.h')]),
    visitors: [Visitor(func: (node) => node.isIncluded = node.name == 'fastsum')],
    output: Output(
      dart: DartOutput(path: root.resolve('lib/src/third_party/fastsum.g.dart')),
      preamble: '// AUTO-GENERATED. Run: dart run tool/ffigen.dart\n'
          '// ignore_for_file: type=lint\n',
    ),
  ).generate();
}
```

```bash
dart run tool/ffigen.dart
```

The bindings use `@Native`, so the asset id comes from the library URI. Wrap them in a safe API, and free what you allocate:

```dart
// lib/fastsum.dart
import 'dart:ffi';

import 'package:ffi/ffi.dart';

import 'src/third_party/fastsum.g.dart' as native;

int sum(List<int> values) {
  final buffer = calloc<Int32>(values.length);
  try {
    buffer.asTypedList(values.length).setAll(0, values);
    return native.fastsum(buffer, values.length);
  } finally {
    calloc.free(buffer);
  }
}
```

## Reading User Defines

An app can configure a dependency's hook from its `pubspec.yaml`, as `sqlite3` does for its encryption build:

```yaml
hooks:
  user_defines:
    fastsum:
      use_prebuilt: true
      local_header: third_party/override.h
```

Read them with `input.userDefines['use_prebuilt']`, or `input.userDefines.path('local_header')` for a path resolved to a `Uri`. Call `output.dependencies.add(uri)` for any file the hook reads, so it reruns when that file changes.

## Tree-Shaking With a Link Hook

On Dart 3.13, a link hook removes native functions nobody calls. Turn on recorded use in the generator with a visitor that sets `node.recordUse = true` on each `Func`, and set `recordUseMapping` in `Output`, which writes a `.g.dart` map from Dart names to C symbols. Add `record_use` as a dependency, and call the matching link method from `hook/link.dart`.

## Downloading Prebuilt Libraries

When you download a binary in a hook, the hook runs on your users' machines, so treat it as a supply-chain boundary. Pin a release, keep a table of SHA-256 hashes per target OS and architecture in the package, and compare each file before using it. A mismatch must fail the build. Offer a user define that falls back to local compilation, so people behind a firewall can still build.

## Verify

```bash
dart run tool/ffigen.dart && git diff --exit-code lib/src/third_party/  # bindings are current
dart analyze
dart test            # runs the hook, then calls the native code
flutter build apk    # or ios, macos: confirms each target compiles
```

Add a test that crosses the boundary, not one that only checks the Dart wrapper:

```dart
// test/fastsum_test.dart
import 'package:fastsum/fastsum.dart';
import 'package:test/test.dart';

void main() {
  test('sums through native code', () {
    expect(sum([1, 2, 3]), 6);
  });
}
```

## Gotchas

1. **`Couldn't resolve native function`.** Symptom: an `ArgumentError` at the first call. Cause: `assetName` doesn't match the bindings' library URI. Fix: align them.
2. **The hook throws with no compiler found.** Symptom: a build failure on a clean machine. Cause: no toolchain. Fix: install one, or use prebuilt downloads.
3. **Changes to the C file aren't picked up.** Symptom: old behaviour after an edit. Cause: the file isn't a declared dependency. Fix: list it in `sources`, or add it to `output.dependencies`.
4. **A crash with no Dart stack trace.** Symptom: the process dies. Cause: a bad pointer in native code. Fix: check lengths in the Dart wrapper, and use a native debugger.
5. **Hooks fail in a workspace.** Symptom: a file-not-found on a relative path. Cause: a path relative to the working directory. Fix: resolve from `input.packageRoot`.
6. **Generated bindings fail analysis.** Symptom: lints or errors in `.g.dart`. Cause: a lint rule, or a parser limit. Fix: add `ignore_for_file` in the preamble for lints. Don't edit the file, and report true errors to `dart-lang/native`.

## Anti-Patterns

- Hand-writing `lookupFunction` when a header exists. Use `ffigen`.
- Hard-coding `DynamicLibrary.open('libfoo.so')`. It breaks on other platforms and defeats hooks.
- Calling `gcc` from a hook. `native_toolchain_c` picks the right compiler per target.
- Downloading without a hash check.

## Pre-Merge Checklist

- [ ] `hooks` and `code_assets` are in `dependencies`
- [ ] Bindings are generated, and regenerating gives no diff
- [ ] Every target platform builds in CI
- [ ] Native memory is freed in a `finally`
- [ ] Downloaded files are verified by SHA-256
